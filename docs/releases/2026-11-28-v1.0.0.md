# Assistant ML Pipeline v1.0.0 — Initial Validated Baseline

**Release date:** 2026-11-28  
**Target branch:** `main`  
**Release baseline:** `779b0029c117e3f6da595729d0bfc2de8adf5a28`

## Summary

This is the first documented baseline release of Assistant ML Pipeline. It captures the working foundation for safe Supabase reads, validated five-intent model training, model publication to Assistant-Service, and the remaining work required to support the complete 23-intent taxonomy.

## Included capabilities

- Automated ML retraining workflow with scheduled and manual execution.
- Read-only Supabase transaction enforcement in the SQLAlchemy connection path.
- Diagnostics that verify the connection is read-only, run `SELECT 1`, and execute a training-style read query without printing sample user data.
- Tests covering the read-only connection and diagnostics.
- A successful retraining run #99 (38 seconds) that cloned Assistant-Service, trained the five-intent model, created branch `ml-model/five-intent-46129540984`, and opened Assistant-Service PR #13.
- Assistant-Service PR #13 was merged; the model update is now included in Assistant-Service main.
- The initial five model intents are `add_to_cart`, `view_cart`, `show_orders`, `track_order`, and `cancel_order`.

## Data and training evidence

The previously reviewed training snapshot used for the five-intent baseline contained 80 reviewed rows, 74 unique normalized examples, and 6 duplicate rows. Deduplication is performed in ML preparation only; source records are preserved. The configured quality gates include at least 10 unique examples per class, an 80/20 holdout, and a 70% accuracy threshold.

These figures describe the recorded training snapshot and gate configuration; they must be refreshed from the database before being treated as the current dataset state.

## Database safety

- Supabase access for training is intended to be read-only.
- Each SQLAlchemy transaction enforces read-only mode and diagnostics verify `transaction_read_only = on`.
- The validation performed no INSERT, UPDATE, DELETE, DDL, or migration operations.
- The ML pipeline's database diagnostics do not establish the state of Assistant-Service conversation tables or ecommerce cart/order databases.

## Scope and known limitations

- This release establishes the five-intent ML baseline only; it does **not** claim that all 23 intents are trained, evaluated, or production-ready.
- The remaining 18 intents require a documented taxonomy mapping across runtime code, reviewed training examples, model coverage, confidence/fallback policy, automated tests, and database evidence.
- Runtime actions such as cart mutation, order tracking, cancellation, and inventory restoration must be implemented and verified in the relevant application/service repositories. Classification alone does not execute those actions.
- Model publication creates a reviewable PR; it does not bypass Assistant-Service CI, review, merge, release, or deployment controls.
